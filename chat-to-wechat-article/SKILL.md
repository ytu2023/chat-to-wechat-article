# 对话转公众号文章

将"用户与 AI 的多轮对话"重构为一篇结构完整、可读性强、适合微信公众号发布的 Markdown 文章。

## 输入形态

- 用户在聊天中直接粘贴的对话记录；
- 用户上传的 txt / md / docx 对话导出文件（用 read_file 读取）；
- 当前对话上文本身就是素材（用户说"把我们的讨论整理成文章"）。

若素材缺失或过短（少于一轮有效问答），先向用户索取对话内容，不要凭空编造讨论细节。

## 工作流程

1. **理解素材**：通读对话，提取核心问题、关键论点、结论、有信息量的追问与纠正。区分"事实性内容"与"探索过程"。
2. **确认定位**（仅当无法从素材判断时询问一次）：
   - 文章类型：技术教程 / 科研笔记 / 观点思考 / 问题排查记录；
   - 目标读者：同行、初学者、还是泛泛的公众号读者；
   - 是否保留"对话感"（如"我问 AI……它指出……"）还是改写为纯陈述文体。默认：**保留少量第一人称叙事，主体改写为陈述文体**。
3. **重构文章**：按 `templates/article-template.md` 的结构产出：
   - 标题：给 3 个候选（一个悬念式、一个干货式、一个问题式），让用户选或默认用第一个；
   - 摘要（digest）：120 字以内，用于公众号摘要栏；
   - 正文：引言（为什么讨论这个问题）→ 核心内容（按逻辑分节，而非按对话轮次堆砌）→ 结论与可复用的经验；
   - 对话中的错误、弯路若对读者有借鉴价值，改写为"踩坑记录"小节，不要简单删除。
4. **去 AI 痕迹**：按 `references/style-guide.md` 检查并消除 AI 腔（堆砌排比、空泛总结、"希望对你有帮助"式结尾、滥用破折号和粗体等）。
5. **公众号适配**：
   - 输出标准 Markdown，兼容 md2wechat / mdnice / 墨滴等排版工具直接粘贴；
   - 小标题用 `##`/`###`，段落宜短，重点句独立成段；
   - 代码块标注语言；公式给出 LaTeX 并提示公众号需用插件渲染；
   - 文末给"封面图建议"（一句画面描述，可用 image_generate 生成，仅在用户需要时）。
6. **交付**：
   - 默认直接在回复中给出全文 Markdown；
   - 用户要求文件时，用 E2B 写入 `/mnt/cos/artifacts/<标题slug>.md` 交付；
   - 若用户进一步要求"排版成公众号样式 HTML"或"推送到草稿箱"，说明这超出本 Skill 范围，推荐配合 md2wechat 类工具完成。

## 质量门槛

- 文章必须忠实于对话内容，不新增对话中不存在的事实、数据或结论；
- 逻辑顺序按"读者理解成本"重排，允许合并、删减闲聊和重复追问；
- 保留用户在对话中的原创观点与个人经历，这是区别于 AI 洗稿的核心价值；
- 全文建议 1500–4000 字；素材不足以支撑时如实告知并建议补充。

## 终止条件

- 用户未提供任何对话素材 → 索取后等待；
- 素材涉密或用户明确表示某些内容不公开 → 剔除并在交付时说明剔除了哪些部分。
